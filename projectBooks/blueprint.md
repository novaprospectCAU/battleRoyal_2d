## 🎯 프로젝트 개요

### 한 줄 요약
> **React 기반 2D 쿼터뷰 배틀로얄 웹게임, 최대 32명 실시간 멀티플레이**

### 핵심 특징
| 항목 | 설명 |
|------|------|
| **플랫폼** | 웹 브라우저 (React) |
| **장르** | 2D 배틀로얄 |
| **시점** | 쿼터뷰 (Isometric-like) |
| **그래픽** | 픽셀아트 또는 간단한 2D 이미지 |
| **플레이어** | 최대 32명 동시 접속 |
| **네트워크** | 실시간 멀티플레이 |

### 핵심 원칙
1. **에셋 독립성**: 에셋이 없어도 게임이 동작해야 함 (디버그 모드)
2. **점진적 개선**: 디버그용 → 실제 에셋으로 전환 가능한 구조
3. **설계 우선**: 코드 작성 전 반드시 설계 문서 작성/검토
4. **문서화**: 모든 결정과 변경사항은 해당 Book에 기록

## 🏗️ 아키텍처 개요

### 계층 구조
```
┌─────────────────────────────────────────────────────────┐
│                    프레젠테이션 계층                      │
│  (React Components, Canvas/WebGL 렌더링, UI/UX)         │
├─────────────────────────────────────────────────────────┤
│                      게임 로직 계층                       │
│  (게임 상태, 물리, 충돌, 전투, 아이템, AI)                │
├─────────────────────────────────────────────────────────┤
│                     네트워크 계층                         │
│  (WebSocket, 상태 동기화, 레이턴시 보정, 매칭)            │
├─────────────────────────────────────────────────────────┤
│                      자원 관리 계층                       │
│  (에셋 로딩, 오디오, 애니메이션, 캐싱)                    │
└─────────────────────────────────────────────────────────┘
```

### 클라이언트-서버 구조
```
┌──────────────┐         WebSocket          ┌──────────────┐
│   Client 1   │◄─────────────────────────►│              │
├──────────────┤                            │              │
│   Client 2   │◄─────────────────────────►│    Server    │
├──────────────┤                            │   (권위적)    │
│     ...      │◄─────────────────────────►│              │
├──────────────┤                            │              │
│  Client 32   │◄─────────────────────────►│              │
└──────────────┘                            └──────────────┘
```

- **권위적 서버 (Authoritative Server)**: 모든 게임 상태의 진실의 원천
- **클라이언트 예측**: 부드러운 사용자 경험을 위한 로컬 시뮬레이션
- **서버 조정**: 클라이언트 예측과 서버 상태 간 보정

## 🎮 핵심 게임플레이 요소

### 1. 배틀로얄 기본 흐름
```
로비 대기 → 게임 시작 → 맵 투하 → 생존 경쟁 → 자기장 축소 → 최후의 1인(팀)
```

### 2. 핵심 메카닉 (상세는 ruleBook.md)
- **이동 & 조작**: 쿼터뷰 8방향 이동
- **전투**: 원거리/근거리 무기, 데미지 시스템
- **아이템**: 무기, 방어구, 회복, 유틸리티
- **자기장**: 시간에 따른 안전 구역 축소
- **루팅**: 맵 곳곳의 아이템 획득

### 3. AI 플레이어 (상세는 npcBook.md)
- 플레이어 부족 시 AI로 채움
- 다양한 난이도/성향의 AI 봇

## ⚠️ 주의사항 및 제약조건

### 기술적 제약
1. **브라우저 환경**: 네이티브 기능 제한
2. **32명 동시 접속**: 네트워크 최적화 필수
3. **실시간 동기화**: 레이턴시 처리 중요
4. **React 렌더링**: 게임 루프와 React 생명주기 분리 필요

### 지켜야 할 원칙
1. **에셋 없이 동작**: 모든 비주얼은 폴백(fallback) 보유
2. **문서 먼저**: 코드 작성 전 해당 Book 업데이트
3. **결정 기록**: 모든 중요 결정은 문서화
4. **테스트 가능**: 기능별 독립적 테스트 가능한 구조
